# セキュリティ・データ取扱ルール

## 1. この文書の目的

本書は、仕入先品質トレンドで扱う認証情報、社内データ、Excel / Power Query / CSV、テストデータ、ログなどの取扱ルールを定める。

---

## 2. 基本原則

- 業務上必要なデータだけを扱う
- GitHubへ保存する情報を最小限にする
- 認証情報をソースコードへ直接記述しない
- 本番データや現行Excel原本を無加工のまま開発やテストに使用しない
- 機密情報や個人情報をログへ出力しない
- 外部サービスや外部AIへデータを送信する場合は、事前に利用可否を確認する
- 不明なデータは、保存・共有する前に人間へ確認する
- Publicリポジトリであることを前提とし、公開可能と確認できた情報だけを保存する

---

## 3. 本プロジェクトで扱うデータの想定

| 種別 | 例 | Git管理 |
|---|---|---|
| 設計文書 | 要件、データ仕様、集計定義 | 可（機密値を含まないこと） |
| 匿名化または架空サンプル | 検証用CSV | 可 |
| 現行Excel原本 | Power Query付き業務ファイル | 不可 |
| 実CSV / 本番データ | 共有フォルダ上の生データ | 不可 |
| 仕入先マスタ原本・実エイリアス | 実仕入先ID・名称を含むファイル | 不可 |
| 実設定 | `config/settings.json` | 不可 |
| 生成された本番JSON | `web/data/dashboard-data.json`等 | 不可 |
| ログ | `logs/error.log`等 | 不可 |
| Power Query参照パス | 社内共有パス | 実装固定・Git記載しない |
| 取引先の実名が残るデータ | 実取引先名付き明細 | 原則不可（匿名化後のみ検討） |

---

## 4. GitHubへ保存してよいもの

原則として、以下はGitHubへ保存できる。

- ソースコード
- 設計文書
- 要件定義
- データ仕様
- カラム定義
- 集計式（確定後）
- テストコード
- 架空データ
- 匿名化済みのサンプルデータ
- 入力ファイルの形式を示す最小サンプル
- 環境変数名だけを記載した`.env.example`
- 機密情報を含まないログ例

ただし、社内ルールや契約上の制限がある場合は、そちらを優先する。

---

## 5. GitHubへ保存してはいけないもの

以下はGitHubへCommit・Pushしてはならない。

- `.env`
- パスワード、APIキー、アクセストークン、Cookie、秘密鍵
- 実在する個人情報、顧客情報、従業員の個人情報
- 取引先から受領した機密情報
- 社外秘の原本データ
- 現行Excel原本、本番CSV、本番データの無加工コピー
- 仕入先マスタ原本、実仕入先名を含むエイリアス設定
- `config/settings.json`
- 生成された本番の`web/data/dashboard-data.json`と`web/data/update-status.json`
- `logs/`配下のログ
- Power Queryが参照する社内共有の実パスを固定した設定
- 実際の社内IPアドレス、IISサーバー名、Windowsアカウント名、本番データパス
- 外部共有を許可されていない社内資料
- 契約上、外部保存が禁止されている情報
- 不要なログや一時ファイル

---

## 6. 社内データ・Excel・CSVの扱い

社内データや現行Excelを扱う場合は、次の順で確認する。

1. アプリ開発に本当に必要なデータか
2. 対象カラムを削減できないか
3. 架空データへ置き換えられないか
4. 匿名化またはマスキングできないか
5. GitHubへ保存する必要があるか
6. 外部AIや外部サービスへ送信してよいか
7. 社内の承認や確認が必要ではないか

GitHubへ保存する必要がない原本データは、Git管理対象外の場所で管理する。

Git管理上の扱い：

- 本番月次CSV・仕入先マスタ：`settings.json`で指定するGit外の場所
- `config/settings.json`：実パスを含むローカル設定（Git管理外）
- `config/supplier-name-aliases.csv`：実仕入先名を含む設定（Git管理外）
- `web/data/`：本番生成JSON（Git管理外）
- `logs/`：実行ログ（Git管理外）
- `data/samples/`：匿名化または架空サンプル（Git管理可）

ExcelやCSVを拡張子単位で一律除外しない。保存場所単位で除外する。

---

## 7. テストデータ

テストデータは、原則として以下のいずれかを使用する。

1. 架空データ
2. 匿名化データ
3. 最小限に加工したサンプルデータ

Excelとの集計一致確認も、匿名化または許可済みの検証データを使用する。

匿名化時には、必要に応じて以下を置換または削除する。

- 氏名
- メールアドレス
- 電話番号
- 住所
- 顧客ID / 従業員ID
- 取引先の機密名称
- 実際の数量・金額のうち業務検証に不要なもの
- 社内管理番号
- 認証情報
- 自由記述欄に含まれる個人情報

業務ルールの検証に不要なカラムは削除する。

---

## 8. 匿名化の確認

匿名化したデータを保存する前に、以下を確認する。

- [ ] 実在する氏名が残っていない
- [ ] メールアドレスが残っていない
- [ ] 電話番号が残っていない
- [ ] 住所が残っていない
- [ ] 個人を特定できるIDが残っていない
- [ ] 自由記述欄に個人情報が残っていない
- [ ] ファイル名に機密情報が含まれていない
- [ ] 複数カラムの組み合わせで個人を特定できない
- [ ] 業務検証に不要なデータを削除している
- [ ] 実取引先名の扱いを確認した

---

## 9. 環境変数

認証情報が将来必要になった場合は、環境変数またはGit管理外の安全な設定で管理する。

MVPの入力パス等は、Git管理外の`config/settings.json`で管理する。

共有用の`settings.example.json`を将来作成する場合は、プレースホルダーだけを記載する。

現時点では必須環境変数はない。

`.env.example`には、実際のパスワード、キー、実絶対パスを記載しない。

---

## 10. ファイルパス

PC固有の絶対パスは、ソースコードやGit管理対象の設計文書へ直接記述しない。

説明が必要な場合は、プレースホルダーのみ使用する。

```text
C:\Users\<ユーザー名>\Desktop\Projects\supplier-quality-trend
```

必要な場合は、環境変数またはGit管理対象外の設定ファイルで管理する。

本番データパスの設定例：

```text
月次CSVフォルダー: <月次CSVフォルダー>
仕入先マスタ: <仕入先マスタファイル>
```

ソースコード内では、環境変数またはリポジトリ直下からの相対パスを使用する。

Power Queryの参照先など、社内共有パスの実値もGitへ記載しない。

IISの予定配置先`C:\var\supplier-quality-trend`と予定物理パス`C:\var\supplier-quality-trend\web`は、環境固有の本番データ参照先ではなく配置例として文書化できる。URLは`http://<社内IISサーバー>/`のようなプレースホルダーで表す。

## 11. `.gitignore`

少なくとも以下をGit管理対象外とする。

```gitignore
.env
.env.*
!.env.example

*.key
*.pem

data/raw/
data/private/
data/production/
secrets/
config/settings.json
config/supplier-name-aliases.csv
web/data/dashboard-data.json
web/data/update-status.json

*.log
logs/

node_modules/
.venv/
venv/

dist/
build/
.next/
```

プロジェクトの採用技術やデータ保存場所に合わせて追加する。  
Excel / CSVは拡張子単位で一律除外しない。

## 12. IIS公開境界

IISでは`web/`だけを公開する。

公開対象：

- `index.html`
- 静的CSS・JavaScript
- Apache ECharts本体とライセンス
- 表示に必要な生成JSON

公開対象外：

- `config/`
- `logs/`
- `tests/`
- `main.py`
- `run.bat`
- 月次CSV、仕入先マスタ、実エイリアス

生成JSONはIISで閲覧可能になるため、表示に不要な元データ、内部パス、ログ、設定値を含めない。

---

## 13. ログ

ログへ以下を出力してはならない。

- パスワード、APIキー、トークン、Cookie
- 個人情報、顧客情報
- 実仕入先ID・実仕入先名
- ローカル絶対パス・UNCパス
- 本番データや現行Excelの全内容
- データベース接続文字列
- 秘密鍵
- 認証ヘッダー

ログには、調査に必要な最小限の情報を記録する。

MVPの`logs/error.log`は、処理日時、例外種別、入力値を含まない固定の処理段階メッセージだけを記録する。

記録例：

- 処理日時
- 処理名
- 成功・失敗
- エラー種別
- 対象件数
- 処理時間
- 匿名化された識別子
- ファイル名（機密を含まないもの）
- エラーが発生した処理段階

---

## 14. エラーメッセージ

利用者向けのエラーメッセージには、内部構造や認証情報を表示しない。

良い例：

```text
データの取込に失敗しました。ファイル形式と必須項目を確認してください。
```

---

## 15. 外部AI・外部サービスへの送信

ChatGPT、外部AI、クラウドサービス、外部APIなどへデータを送信する場合は、以下を確認する。

- 送信してよいデータか
- 個人情報を含んでいないか
- 社外秘のExcel / CSVを含んでいないか
- 匿名化できないか
- 最小限のカラムだけにできないか
- 社内の利用ルールに違反しないか
- 契約や機密保持義務に違反しないか

判断できない場合は、送信せず人間へ確認する。

---

## 16. データ保存期間

不要になった以下のデータは削除する。

- テスト用の一時ファイル
- デバッグ用出力
- 不要になったログ
- 古いエクスポートファイル
- 調査用に複製したデータ

保存期間が必要な場合は、アプリ固有の要件として定義する。

---

## 17. Commit前の確認

Commit前に以下を確認する。

- [ ] `.env`を含んでいない
- [ ] APIキーやパスワードを含んでいない
- [ ] アクセストークンを含んでいない
- [ ] 個人情報を含んでいない
- [ ] 顧客情報を含んでいない
- [ ] 本番データ・現行Excel原本を含んでいない
- [ ] 仕入先マスタ原本・実エイリアスを含んでいない
- [ ] `config/settings.json`を含んでいない
- [ ] 生成された本番JSON・ログを含んでいない
- [ ] 実際の社内IPアドレス、IISサーバー名、Windowsアカウント名、本番データパスを含んでいない
- [ ] PC固有の実絶対パスを実装や文書へ固定していない
- [ ] 不要なログを含んでいない
- [ ] サンプルデータは匿名化されている
- [ ] 一時ファイルを含んでいない
- [ ] Git差分を確認した

確認コマンド：

```powershell
git status
git diff
git diff --cached
git diff --check
```

---

## 18. 誤って機密情報をCommitした場合

1. 直ちにPushを停止する
2. 対象の認証情報を無効化する
3. パスワード、APIキー、トークンなどを再発行する
4. Git履歴からの削除方法を確認する
5. 必要に応じて管理者または関係者へ報告する
6. 漏えい範囲を確認する
7. 再発防止策を記録する

---

## 19. セキュリティ上の判断が必要な場合

Cursorは、セキュリティやデータ取扱いについて不明な点を推測で決定してはならない。

以下の場合は作業を停止し、人間へ確認する。

- GitHubへ保存してよいか判断できない
- 本番データや現行Excel原本を使用する必要がある
- 外部サービスや外部AIへデータを送信する必要がある
- 認証方式を変更する
- 権限設計を変更する
- 個人情報や顧客情報を扱う
- 秘密情報を新たに保存する必要がある
