# 要件定義（TO-BE）

## 1. 業務要件

| ID | 要件 | 背景・目的 | 優先度 |
|---|---|---|---|
| BR-001 | 仕入先ごとの月別現行不良率推移をWebで確認できる | Excel依存を減らし、ブラウザから確認できるようにする | Must |
| BR-002 | 現行Excelと同一条件で集計結果が一致する | 現行業務との連続性を優先する | Must |
| BR-003 | 単一の`SHIIRESAKI_ID`と仕入先グループを切り替えて閲覧できる | ID分割や表記揺れを含む仕入先を適切な単位で確認する | Must |
| BR-004 | 現行指標の分母制約を利用者へ明示する | 仕入先全体の正式な不良率と誤認させない | Must |
| BR-005 | 更新失敗時に前回正常データを維持する | 閲覧可能な状態を保つ | Must |

## 3. 非機能要件

### 性能

- 想定データ量・目標応答時間は未確定
- バッチの最大実行時間は30分とする

### セキュリティ

- Publicリポジトリへ実データ、仕入先マスタ原本、実設定、生成された本番JSON、ログ、認証情報、個人情報を含めない
- IISでは`web/`だけを公開し、`config/`、`logs/`、`tests/`、`main.py`、`run.bat`を公開しない
- 詳細は`docs/08_security-and-data-handling.md`を参照

### 可用性・バックアップ

- JSONは一時ファイルへ出力し、全検証成功後に本番ファイルと置換する
- 更新失敗時は前回正常データを維持する
- タスクを二重起動しない

### 保守性

- 集計定義・除外条件を文書化し、UIへ直書きしない
- Pythonは型ヒントを使用し、標準ライブラリを優先する
- コードコメントは日本語、コンソール出力は英数字のみとする

### 対応環境

- Python 3.14
- 静的HTML／CSS／JavaScriptとApache ECharts
- 社内IISによる静的配信
- 対象ブラウザはMicrosoft Edge、Google Chrome、Mozilla Firefoxの各最新版

## 5. データ更新方法

- Pythonファイル名：`main.py`
- BATファイル名：`run.bat`
- 手動実行：`run.bat`
- 定期実行：`run.bat scheduled`
- Windowsタスクスケジューラで毎週月曜日午前8時に実行する
- 開始時刻を逃した場合は可能になり次第実行する
- 失敗時は10分間隔で最大3回再試行する
- 元ファイルの取得方法と配置担当者は未確定

## 6. エラー時の動作

| ケース | 表示内容 | 記録 | 再実行方法 |
|---|---|---|---|
| 必須カラム不足、入力・設定・出力の読込失敗、エイリアス競合 | 更新失敗を表示し、前回正常データを維持する | `logs/error.log` | 原因修正後に再実行 |
| 重複、100％以上、マスタ未登録、名称差異、欠損月、照合不一致、`SYUKKA_SU=0`、当月CSVがヘッダー行のみ | 警告を表示して処理を継続する | 表示用警告とログ | 必要に応じてデータ確認 |
| `SYUKKA_SU=0` | 数量を保持して集計対象に含め、不良率を「算出不可」と表示する | `ZERO_SHIPMENT_QUANTITY`警告を残す | データ確認後に再実行 |
| `HENPIN_SU`・`SYUKKA_SU`の空欄、非数値、非有限値、負数、非整数 | 該当行全体を集計対象外にする。有効行が残る場合は処理を継続する。`1.0`・`2.00`など数値として整数の値は有効とする | ファイル名、行番号、カラム名、元値を警告へ記録する | データ確認後に再実行 |
| 実行日（JST）の当月CSVがヘッダー行のみ | 集計対象外とし処理を継続する。最新データ月は有効行がある最新月とする | `EMPTY_CURRENT_MONTH_FILE`警告を`dashboard-data.json`へ残す | 当月データ投入後に再実行 |
| 過去月CSVがヘッダー行のみ、またはデータ行はあるが有効行0件 | 更新失敗を表示し、前回正常データを維持する | `EMPTY_MONTHLY_FILE`または不正数量の警告詳細を記録する | データ修正後に再実行 |
| 当月CSVにデータ行はあるが全行不正で有効行0件 | 更新失敗を表示し、前回正常データを維持する | 不正数量の警告詳細を記録する | データ修正後に再実行 |
| 当月の空CSVしかなく有効な月次データがない | 更新失敗とし、前回正常JSONがあれば維持する。なければダッシュボードJSONを新規生成しない | `EMPTY_CURRENT_MONTH_FILE`警告を記録する | 有効な月次データを配置して再実行 |
| `DEFECTIVE_RATE`と再計算値の絶対差が`1E-12`を超える | 集計値へ影響させず処理を継続する | `DEFECTIVE_RATE_MISMATCH`警告を残す | 必要に応じてデータ確認 |

## 9. 画面構成

上部：

- 単一仕入先／仕入先グループ切替
- 国内／海外絞り込み
- 仕入先ID・名称検索
- 開始月、終了月
- 最終更新日時、最新データ年月、警告件数

KPI：

- 最新月現行不良率
- 前年同月現行不良率
- 前年同月差
- 最新月返品数、最新月出荷数
- 期間全体現行不良率

主グラフ：

- 現行不良率の折れ線
- 目標1％基準線
- 目標超過、集計途中、100％以上の異常値、欠損月の識別表示
- ツールチップに対象月、返品数、出荷数、不良率、状態を表示

詳細表：

- 対象年月、出荷数、返品数、現行不良率、目標判定、データ状態、警告

空状態・エラー状態：

- 仕入先未選択、該当データなし、対象期間不正、最新更新失敗、一部警告あり
- 仕入先マスタ未登録、欠損月、集計途中、前年同月データなし
- 設定エラー、生成データ未作成

## 10. 画面注釈

次の趣旨を画面上へ常時表示または情報表示する。

> 本画面の不良率は、当月に出荷した商品のうち、返品が発生したSKUの出荷数を分母として算出しています。返品が発生していないSKUの出荷数は分母に含まれないため、仕入先全体の正式な不良率とは異なります。現行集計条件に基づく傾向確認用の指標として参照してください。集計条件により、100％を超える場合があります。
