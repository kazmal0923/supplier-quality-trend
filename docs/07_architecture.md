# アーキテクチャ

## 1. この文書の目的

本書は、仕入先品質トレンドの技術構成、主要コンポーネント、データフロー、ディレクトリ構成を記録する。

業務要件は`docs/02_requirements.md`、データの詳細仕様は`docs/03_data-specification.md`、個別の重要な設計判断は`docs/decisions/`で管理する。

---

## 2. 設計の基本方針

- 業務仕様と技術仕様を分離する
- 画面表示と業務ロジックを分離する
- データアクセス処理と業務ロジックを分離する
- 計算式をUIへ直接記述しない
- 同じ業務ルールを複数箇所へ重複実装しない
- 各処理をテスト可能な単位へ分割する
- 特定PCの絶対パスへ依存しない
- 環境固有の値は環境変数または設定ファイルで管理する
- 将来の変更範囲を限定できる構成にする

---

## 3. システム概要

```text
利用者（商品部 / 品質管理担当）
  ↓
Webブラウザ
  ↓
IIS（web/のみ静的配信）
  ├─ HTML / CSS / JavaScript
  ├─ Apache ECharts
  └─ 表示用JSON

Windowsタスクスケジューラ / 手動実行
  ↓
run.bat
  ↓
Python 3.14（main.py）
  ├─ 月次CSV・仕入先マスタ・設定の読込
  ├─ 検証・マスタ結合・エイリアス適用
  ├─ 単一ID・グループ集計
  └─ JSON一時出力・原子的置換
```

データベースと常駐Pythonサーバーは使用しない。Pythonバッチが静的な表示用JSONを生成し、IISは`web/`だけを公開する。

## 5. 主要コンポーネント

### 5.1 ユーザーインターフェース

役割：

- 単一仕入先／仕入先グループの切替
- 国内／海外絞り込みとID・名称検索
- 開始月・終了月指定
- KPI、折れ線グラフ、詳細表の表示
- 目標超過、異常値、欠損月、集計途中、更新状態の表示
- 現行指標の制約注釈の情報表示（初期折りたたみ、展開で全文）

UIには、複雑な業務計算やデータアクセス処理を直接記述しない。

任意期間の期間全体現行不良率は、Pythonが生成した月別集計済みの返品数・出荷数をブラウザで合算して再計算する。ブラウザへ明細データやCSV解析処理を持ち込まない。

---

### 5.2 データ取込・検証

役割：

- `YYYY年MM月.csv`をUTF-8で一括読込する
- 仕入先マスタをCP932で読み込む
- Git管理外の設定とエイリアスを読み込む
- ファイル名から対象年月を取得する
- 必須カラムを検証する
- 数値、重複、マスタ未登録、名称差異、欠損、照合不一致を検出する
- 取込結果を記録する

基幹システムやBoxから元ファイルを自動取得する処理はMVP対象外とする。

---

### 5.3 業務ロジック

役割：

- 確定した業務ルールを適用する
- 月別・期間全体現行不良率を数量合計から算出する
- 現在名称の完全一致とエイリアスで仕入先グループを作成する
- 目標判定、前年同月比較、当月判定を行う
- 欠損値・重複データと警告状態を処理する
- Excel集計結果との比較検証を支援する

業務ロジックは、画面や保存方式から独立してテストできる構成にする。  
0除算表示、異常入力、照合許容差は`docs/03_data-specification.md`の確定仕様を適用する。

---

### 5.4 静的データ生成

役割：

- `web/data/dashboard-data.json`を生成する
- `web/data/update-status.json`へ更新日時・結果・警告状態を出力する
- JSONを一時ファイルへ出力し、全検証成功後に本番ファイルと置換する
- 更新失敗時は前回正常データを維持する
- WindowsのOSファイルロックで二重起動を防止し、正常終了・異常終了のどちらでもプロセス終了時にロックが解放される

生成JSONはスキーマバージョン1とし、詳細は`docs/03_data-specification.md`で管理する。

---

### 5.5 ログ・エラー処理

役割：

- 処理の成功・失敗を記録する
- エラー原因を利用者へ表示する
- 機密情報や実データをログへ出力しない
- 入力エラーとシステムエラーを区別する
- 手動実行とスケジュール実行で終了・一時停止の動作を分ける

---

## 6. データフロー

```text
月次CSV検出・ファイル名検証
  ↓
UTF-8で読込・対象年月付加
  ↓
仕入先マスタをCP932で読込
  ↓
SHIIRESAKI_IDで結合・現在名称付加
  ↓
エイリアス適用
  ↓
単一ID・グループ単位の数量集計
  ↓
月別・期間全体現行不良率、前年同月、警告を計算
  ↓
JSONを一時ファイルへ出力・検証
  ↓
全検証成功後に本番JSONと置換
  ↓
update-status.jsonへ更新結果を出力
  ↓
IISで静的配信
```

更新失敗時は本番JSONを置換せず、前回正常データを維持する。

## 7. ディレクトリ構成

MVP実装構成：

```text
supplier-quality-trend/
├─ supplier_quality_trend/
│  ├─ __init__.py
│  └─ 責務別Pythonモジュール
├─ config/
│  ├─ settings.example.json
│  ├─ settings.json                 # Git管理外
│  └─ supplier-name-aliases.csv     # 実設定はGit管理外
├─ docs/
├─ logs/                            # Git管理外
├─ tests/
├─ web/
│  ├─ index.html
│  ├─ data/
│  │  ├─ dashboard-data.json        # 本番生成物はGit管理外
│  │  └─ update-status.json         # 本番生成物はGit管理外
│  └─ vendor/echarts/
│     ├─ echarts.min.js
│     └─ LICENSE.txt
├─ AGENTS.md
├─ main.py
├─ run.bat
└─ README.md
```

本作業では上記のアプリファイルや設定ファイルを作成しない。

### ディレクトリ設計の原則

- Python処理を取込、検証、集計、出力の責務に分割する
- Python内部識別名に合わせて`supplier_quality_trend/`パッケージへ配置し、`main.py`は薄いエントリーポイントとする
- 業務ロジックをUIへ混在させない
- 一時ファイルや本番データをGit管理しない
- サンプルデータは匿名化する
- Windowsアカウント名や本番データパスを固定しない
- ユーザーホームは`Path.home()`で取得し、環境ごとの差異はGit管理外の設定で吸収する
- アプリディレクトリは`main.py`の配置場所を基準に取得する

## 8. 環境構成

| 環境 | 用途 | 使用データ | 備考 |

| ローカル | 開発・単体テスト | 架空または匿名化データ | 各PCで構築 |

## 11. 非機能設計

以下をアプリごとに確認する。現時点は未確定が多い。

### 性能

- 想定利用者数：未確定
- 想定データ件数：未確定
- 目標応答時間：未確定

### 可用性

- 更新失敗時は前回正常データを維持する
- タスクは二重起動せず、最大実行時間30分とする
- 利用時間帯、バックアップ方式は未確定

### 保守性

- 集計定義はdocsとPythonの業務ロジック層で管理する
- Pythonは型ヒントを使用し、標準ライブラリを優先する
- コードコメントは日本語、コンソール出力は英数字のみとする
- ログへ機密情報を出さない

### 対応環境

- バッチ実行環境：Windows、Python 3.14
- Web配信：IIS
- 対応ブラウザ：Microsoft Edge、Google Chrome、Mozilla Firefoxの各最新版

### セキュリティ

- Publicリポジトリへ実データ、実設定、生成された本番JSON、ログを含めない
- IISでは`web/`だけを公開する
- 詳細は`docs/08_security-and-data-handling.md`
