# ADR-002 Python静的生成とIIS配信

- 状態：採用
- 決定日：2026-08-03

## 背景

MVPでは、現行Excelと同一条件の集計を定期的に再生成し、社内利用者がブラウザから確認できる構成が必要である。

本番データと実設定をPublicリポジトリへ含めず、データベースや常駐アプリケーションサーバーを運用しないことも要件である。

## 決定

- Python 3.14の`main.py`で入力ファイルを読み込み、検証・集計・静的JSON生成を行う
- Windowsタスクスケジューラから`run.bat scheduled`を毎週月曜日午前8時に実行する
- 開始時刻を逃した場合は可能になり次第実行し、失敗時は10分間隔で最大3回再試行する
- 二重起動を防止し、最大実行時間を30分とする
- JSONは一時ファイルへ出力し、全検証成功後に本番ファイルと置換する
- 更新失敗時は前回正常データを維持する
- 画面は静的HTML／CSS／JavaScriptで構築する
- 任意期間の期間全体現行不良率は、Pythonが生成した月別集計済み数量をブラウザで合算して再計算する
- グラフにはApache EChartsを使用し、CDNを使わずライセンスとともにアプリ内へ配置する
- IISでは`web/`だけを静的配信する
- データベースと常駐Pythonサーバーは使用しない

## 理由

- 社内IISの静的配信に適合する
- サーバー常駐プロセスとデータベースの運用を不要にできる
- 更新処理と閲覧処理を分離できる
- 更新失敗時も前回正常データを継続表示できる
- Publicリポジトリへ本番入力や実設定を保存せずに運用できる

## 影響

- 画面は生成済みJSONだけを参照し、CSV解析や仕入先・グループ単位の明細集計は行わない
- 入力パス等はGit管理外の`config/settings.json`で管理する
- 本番CSV、仕入先マスタ、実エイリアス、生成された本番JSON、ログはGit管理しない
- Apache ECharts 6.1.0をアプリ内へ配置し、Microsoft Edge、Google Chrome、Mozilla Firefoxの各最新版を対象とする
- IISの実URL、アクセス権、タスク実行アカウントは移植時に確認する

実行モードとタスク設定の詳細は`docs/02_requirements.md`および`docs/06_development-setup.md`を正とする。

## 代替案

### 常駐Python Webサーバー

動的処理が可能だが、MVPでは常駐プロセスの運用が不要なため採用しない。

### データベース

検索・履歴管理を拡張しやすいが、MVPのファイルベース集計には過剰なため採用しない。

### CDNからApache EChartsを取得

外部接続へ依存するため採用しない。
